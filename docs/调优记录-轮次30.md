# 调优记录 · 轮次 30：接受阈值绕不开采样崩溃，但失败方式指认了另一件事

日期：2026-08-14
承接：轮次 29（把采样崩溃定位到「拒绝后重采样」分支）

## 一、推论与实验

轮次 29 证明触发条件是**拒绝事件**：`top_k=1` 时接受率高、重采样分支不进，8 并发安全；
`top_k=2` 时接受率掉到 0.25，立刻复现 `HSA_STATUS_ERROR_EXCEPTION 0x1016`。

由此有个直接推论：**如果能把接受率抬回去，拒绝事件变少，是不是就绕开了？**

sglang 正好有两个旋钮：

```
--speculative-accept-threshold-acc     接受概率由目标概率 p 抬到 min(1, p / threshold_acc)
--speculative-accept-threshold-single  目标概率大于此阈值即接受草稿 token
```

`threshold_acc` 调小 → `p / threshold_acc` 变大 → 接受概率抬高。于是取激进值
`acc=0.1`、`single=0.05` 重启，跑 8 并发全采样（不传 `top_k`），全程只用贪心热身。

## 二、结果：不但没绕开，阈值根本没起作用

| 观察项 | 默认阈值（轮次 29） | **acc=0.1 / single=0.05（本轮）** |
|---|---|---|
| 贪心单流 | 33.2 tok/s | **33.15 tok/s**（无变化） |
| 贪心 accept rate | 0.60–0.77 | **0.59–0.79**（无变化） |
| 8 并发采样结果 | 2/8 超时 | **3/8 成功，5 个超时** |
| 采样 accept rate | 0.26–0.27 | **0.27**（无变化） |
| `HSA_STATUS_ERROR_EXCEPTION` | 出现 | **出现 5 次** |

**关键不是"没绕开"，而是 accept rate 一点没动。**

阈值从默认放宽到极激进（`acc=0.1` 意味着任何 p>0.1 的草稿 token 都该被直接接受），
采样下的接受率却仍然牢牢停在 0.27，与轮次 29 完全一致；贪心下的接受率同样纹丝不动。

## 三、结论：这两个阈值管不到采样路径

唯一自洽的解释是：**`--speculative-accept-threshold-*` 只作用于确定性接受路径
（典型接受 / typical acceptance），采样模式走的是另一套接受逻辑，不读这两个参数。**

这正好和轮次 29 的定位互相印证——采样模式确实走在一条独立的分支上，而那条分支：

- 不受接受阈值控制（本轮）
- 不受 `SGLANG_DSPARK_FORCE_TORCH_ACCEPT` 控制（轮次 24 已试，无效）
- 只要拒绝事件密集发生就会炸（轮次 29）

换句话说，**这条分支目前在应用层没有任何可控入口**。三个看起来最相关的开关，
一个管不到它，一个换错了地方，剩下的只能靠回避（贪心或 `top_k=1`）。

> 顺带确认了一件好事：把接受阈值放到极激进值，**贪心性能毫发无损**（33.15 vs 33.2）。
> 也就是说这两个参数对我们当前的贪心生产配置是中性的，不必担心误设带来性能回退。

## 四、目前唯一可用的采样缓解手段

轮次 29 的 `top_k=1` 仍然是唯一在 8 并发下验证通过的采样配置（8/8，聚合 48.9 tok/s）。

实用建议：**网关层对 `temperature>0` 的请求强制注入 `top_k=1`**，而不是直接拒绝。

- 好处：API 兼容性保住了（客户端照常传 temperature），服务不崩
- 代价：输出实质上是确定性的，拿不到采样的多样性
- 边界：`top_k=2` 就会炸，没有中间地带

这比"禁止 temperature>0"温和，但要清楚它并没有真正恢复采样能力。
**真正的修复只能在厂商侧**，诉求见轮次 29 第五节。

## 五、本轮之后的状态

至此，围绕采样崩溃的应用层手段已全部试遍：

| 手段 | 结果 |
|---|---|
| draft 块大小 / 稀疏 top_k / 运行批量限流 / JIT moe_align / 降并发 | 轮次 24 全部无效 |
| `SGLANG_DSPARK_FORCE_TORCH_ACCEPT` | 无效（换掉的不是出问题的分支） |
| 预热非贪心路径 | 部分有效（安全并发 2→4），治标 |
| **接受阈值放宽** | **无效（阈值管不到采样路径）** |
| **`top_k=1`** | **有效，但等价于放弃采样多样性** |

解码速度方向（轮次 25–28）与采样可用性方向（轮次 24、29、30）**都已收敛到厂商侧**。
应用层剩下的只有预填充侧几项未测小项（`--cuda-graph-backend-prefill`、
`chunked-prefill-size`、`--moe-runner-backend` 备选、共享专家融合强开），
均不触及已定位的两个瓶颈。
